# 预约时间：数据库与接口契约

- 版本：v1.0 追加件（预约时间能力）
- 状态：交后端队友按本文档实现服务端；前端已按「本地演示存储 + 契约文档」先行落地
- 对接基线：沿用 `docs/api-contract.md`（v1.0）的**全部全局约定**（信封 / 错误码 / ID 前缀 / 时间格式 / 幂等），本文档不另立新规则，只**新增**预约时间这一块

> 本文档只描述「预约时间」的新增数据库与接口。问卷 / 树洞 / 档案 / 分流等既有能力一律不动。

## 1. 追加的全局约定（增量）

| 项 | 约定 |
|----|------|
| 新增 ID 前缀 | `apt_`（预约记录；与既有 `stu_ / tch_ / rec_ / tre_ / tkt_ / alt_` 并列） |
| 存储格式 | **JSON Lines**（一行一个 JSON object），与服务端既有数据文件同款 |
| 时间字段 | 「预约时间」用裸字段 `year/month/day/time`（`YYYY` / `MM` / `DD` / `HH:MM`）；「记录生成时间」用 `created_ts`（ISO 8601 带时区） |
| 幂等 | 写接口携带客户端生成的 `apt_id`；重复提交返回首次结果，不重复写库 |

## 2. 预约时间数据库表结构

字段名与前端本地演示文件 `appointments.jsonl` **逐字节对齐**（服务端同名表必须可无缝替换）。

| 字段 | 类型 | 说明 |
|------|------|------|
| `apt_id` | string | 预约记录 ID，`apt_` 前缀 + 随机串（客户端生成、幂等键） |
| `student_id` | string | 预约人 ID，`stu_` 前缀 |
| `name` | string | 预约人姓名 |
| `class_name` | string \| null | 预约人班级 |
| `year` | string | 预约年份，`YYYY` |
| `month` | string | 预约月份，`MM` |
| `day` | string | 预约日，`DD` |
| `time` | string | 预约时间段（起始钟点），`HH:00`（前端给出 09:00–17:00 整点） |
| `share_questionnaire` | boolean | 是否把该生的测评问卷正文一并给老师看（选择性发送） |
| `share_treehole` | boolean | 是否把该生的树洞记录一并给老师看（选择性发送） |
| `created_ts` | string | 记录创建时间，ISO 8601 带时区 |

样例行：

```json
{"apt_id":"apt_01J8ZEXAMPLE","student_id":"stu_2023001","name":"林小满","class_name":"高一(2)班","year":"2026","month":"10","day":"3","time":"15:00","share_questionnaire":true,"share_treehole":false,"created_ts":"2026-10-02T22:31:05+08:00"}
```

**选择性发送语义**：`share_questionnaire` / `share_treehole` 只是**布尔标记**，表内**不落正文**。
老师端查预约时，仅当对应标记为 `true`，才按 `student_id` + 预约日期去关联读取
`questionnaire/submissions` 与 `treehole/entries` 的正文；为 `false` 时只给老师看
「姓名 / 班级 / 预约时间」，正文一律不暴露。

## 3. 新增接口

### 3.1 POST /appointments（学生）

学生端在「请求心理老师帮助」→ 选完预约时间后调用，创建一条预约记录。

请求：

```json
{
  "apt_id": "apt_01J8ZEXAMPLE",
  "year": "2026",
  "month": "10",
  "day": "3",
  "time": "15:00",
  "share_questionnaire": true,
  "share_treehole": false
}
```

- `apt_id` 由客户端生成（幂等键），`student_id / name / class_name` 由服务端从 token 的 profile 推导，**不信任客户端**；
- `share_questionnaire` / `share_treehole` 缺省 `false`；
- `year / month / day / time` 任一缺失或格式非法 → `2001`（message 带字段名）。

响应 `data`：

```json
{
  "apt_id": "apt_01J8ZEXAMPLE",
  "created_ts": "2026-10-02T22:31:05+08:00"
}
```

### 3.2 GET /appointments?date=YYYY-MM-DD（教师）

老师端按日期拉取预约清单（`date` 对应 `year-month-day`）。

响应 `data`：

```json
{
  "date": "2026-10-03",
  "items": [
    {
      "apt_id": "apt_01J8ZEXAMPLE",
      "student_id": "stu_2023001",
      "name": "林小满",
      "class_name": "高一(2)班",
      "time": "15:00",
      "share_questionnaire": true,
      "share_treehole": false,
      "questionnaire": [ { "record_id": "rec_...", "mood": "down", "cause_category": "study", "detail": "……" } ],
      "treehole": [ { "entry_id": "tre_...", "content": "……" } ]
    }
  ]
}
```

- `questionnaire` / `treehole` 仅在对应标记为 `true` 时**才**含正文，否则为 `null`；
- 排序：按 `time` 升序；
- 权限纪律：`1002` —— 学生角色访问本接口即拒；本接口不得泄露**未勾选分享**学生的任何正文。

## 4. 与既有流程的关系（前端行为口径）

1. 学生端在求助选择页点「请求心理老师帮助」→ **不直接提交**，先跳到预约时间选择页；
2. 学生选「年 / 月 / 日 / 时间段」并可选勾选「测评内容 / 树洞」→ 点「确认预约」；
3. 前端先落预约（本地 `appointments.jsonl` / 联调后 `POST /appointments`），
   **再**走既有的一次性 `POST /questionnaire/submissions`（请求体仍是 v1.0 的 8 字段，**预约数据不混入问卷提交体**）。
